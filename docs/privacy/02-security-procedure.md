# נוהל אבטחת מידע — ברק שירותים

> טיוטה לפי תקנה 4 לתקנות אבטחת מידע (רמה בינונית). קצר בכוונה — עסק של אדם אחד עד כמה רכזים. מה שכתוב כאן צריך להיות נכון בפועל; אם משהו לא מתאים — לשנות את הנוהל או את המציאות, לא להשאיר פער.

**אחראי לנוהל:** מנהל המאגר (סער). **עדכון:** אחת לשנה או אחרי אירוע אבטחה. **גרסה:** 0.1 · 2026-08-19

## 1. היקף
כל המערכות שמחזיקות מידע על מועמדים/לקוחות: אפליקציית lead-management (Vercel + Supabase), תיבות המייל של העסק (Google Workspace), המספר העסקי בוואטסאפ (GreenAPI), קבצי Excel/Sheets של pipeline, מחשבים וטלפונים של הרכזים.

## 2. הרשאות גישה
1. גישה למערכת רק דרך משתמש אישי (אימייל + סיסמה) ב-Supabase Auth. **אין משתמשים משותפים.**
2. פתיחת משתמש: רק ע"י מנהל המאגר, אחרי חתימת הרכז/ת על התחייבות לסודיות (נספח א').
3. סגירת משתמש: **באותו יום** של סיום עבודה — מחיקה ב-`הגדרות → משתמשים` + החלפת סיסמאות משותפות (GreenAPI, Gmail של הסקרייפר) אם היו חשופות.
4. סיסמאות: 12+ תווים, ייחודיות, במנהל סיסמאות. **MFA** — `[להפעיל ב-Supabase Auth ולחייב]`.
5. מפתחות מערכת (`SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, `API_SECRET_KEY`, `GREEN_API_TOKEN`, `ANTHROPIC_API_KEY`, `GMAIL_*`): רק ב-Vercel env + `.env.local` במחשב מנהל המאגר. לא בצ'אטים, לא בגיט (`.gitignore` מכסה `.env*`). **החלפה:** אחת לשנה, ומיד אם רכז/ת עם גישה למחשב עוזב/ת.
6. סקירת הרשאות: אחת לרבעון — רשימת משתמשים ב-`הגדרות → משתמשים` מול רשימת העובדים בפועל.

## 3. תיעוד גישה (תקנה 10)
- המערכת רושמת אוטומטית ב-`audit_log`: מי, מתי, איזו רשומה, איזו פעולה (צפייה, עדכון עם ערכים לפני/אחרי, שינוי סטטוס, ייצוא, מחיקה), IP.
- שמירה: 24 חודש, מחיקה אוטומטית אחר כך.
- **בדיקה תקופתית:** אחת לחודש מנהל המאגר מריץ:
  ```sql
  select actor, action, count(*) from audit_log
   where occurred_at > now() - interval '30 days' group by 1,2 order by 3 desc;
  ```
  ומחפש חריגים: ייצוא (`export`) שלא זכור, צפיות מרובות של משתמש בשעות לא סבירות, מחיקות.
- הלוג אינו ניתן לעריכה/מחיקה ע"י משתמשים.

## 4. אבטחת התקנים
- מחשב/טלפון שניגש למערכת: נעילת מסך אוטומטית (≤5 דק'), הצפנת דיסק (BitLocker/FileVault), עדכוני מערכת הפעלה מופעלים, אנטי-וירוס.
- **אסור** לשמור ייצוא של לידים (CSV/JSON) על מחשב אישי מעבר לזמן העבודה. קבצים כאלה נמחקים אחרי השימוש.
- אין גישה למערכת מהתקנים משותפים/ציבוריים.
- וואטסאפ עסקי: המכשיר שמחובר ל-GreenAPI נעול, גיבוי ענן של WhatsApp **כבוי** (הגיבוי לא מוצפן).

## 5. תקשורת ורשת
- כל התעבורה HTTPS (Vercel/Supabase כופים). אין גישה ישירה ל-DB מהאינטרנט חוץ מ-pooler עם סיסמה — הסיסמה רק אצל מנהל המאגר.
- webhook נכנס (GreenAPI → `/api/whatsapp`): `[להגדיר webhook token בקונסול GreenAPI ולבדוק אותו בקוד]`.
- Cron routes מוגנים ב-`CRON_SECRET`; API חיצוני ב-`API_SECRET_KEY`.

## 6. הפרדת סביבות ומידע
- פרודקשן = פרויקט Supabase פרנקפורט. פרויקט טוקיו הישן — `[למחוק / לוודא ריק]` (נשמר כ-rollback; אחרי 30 יום מהמעבר — למחוק).
- אין העתקת נתוני אמת לסביבת פיתוח מחוץ למחשב מנהל המאגר.
- מסמכים רגישים (ת.ז., טופס 101) נשמרים **רק** ב-bucket `lead-documents`, לא במייל ולא בוואטסאפ מעבר לרגע הקבלה — `[להוריד לבucket ולמחוק מהצ'אט]`.

## 10. אירוע אבטחה — מה עושים
"אירוע אבטחה חמור" (תקנה 11) ברמה בינונית = שימוש במידע ללא הרשאה או פגיעה בשלמותו לגבי **חלק מהותי** מהמאגר.

1. **לעצור את הדימום** — לבטל מפתח/סיסמה/משתמש שנפרץ; אם צריך — להוריד את האתר (Vercel → Pause).
2. **לתעד** בטופס נספח ב': מתי התגלה, מה קרה, אילו נתונים, כמה נושאי מידע, מה נעשה.
3. **לדווח לרשות להגנת הפרטיות מיידית** (טופס דיווח באתר הרשות) — אם זה אירוע חמור. בספק → מדווחים.
4. **להודיע לנושאי המידע** אם הרשות דורשת או אם יש סיכון ממשי להם.
5. **תחקיר** תוך 14 יום: סיבת שורש, תיקון, עדכון הנוהל.
6. פרטים לדיווח: מנהל המאגר `saar@eilatjobs.com`, `[טלפון]`; DPO `[ ]`.
